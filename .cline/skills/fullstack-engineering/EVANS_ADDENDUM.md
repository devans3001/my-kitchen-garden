# Evans Addendum: read alongside SKILL.md, always

Added Nov 1, 2026 when this skill was adopted. The base skill
governs engineering. These local rules govern how work is done
for Evans specifically, and they win wherever the two differ.

## Design authority

On any client-facing or public-facing build, visual direction
belongs to the captivating_web_design skill
(~/workspace/custom-skills/captivating_web_design/SKILL.md):
reference anchor, named direction, one-sentence spine, real
client material first, screenshot audit before Evans sees
anything. This skill governs the engineering underneath
(structure, data, auth, tests, deployment). Competent but
generic UI is a failed build here, however clean the code is.

## Delivery reality

- Finished client websites are pushed to a GitHub repo for
  Vercel hosting or a bought domain. Evans creates the repos.
  The GitHub connection pushes text files into existing repos
  only: it cannot create repos, delete files, or transfer
  binary images. Images are hotlinked from online CDNs or
  uploaded by Evans himself.
- One build at a time. Show the build first. Push or publish
  only when Evans says he is satisfied. A general approval
  covers that version only, never the next one.
- Resolve a project's real live address through Vercel before
  claiming anything is live. A guessed or bare slug address
  can belong to a different project.

## House rules

- No em dashes in any copy, draft, caption, or user-facing
  text. Full stops and commas instead.
- Never invent client facts: no fabricated prices, ratings,
  reviews, or testimonials. If a fact is not published or
  verified, it does not appear in the build.
- Money is tight by default: prefer zero-cost options unless
  Evans names a budget.
